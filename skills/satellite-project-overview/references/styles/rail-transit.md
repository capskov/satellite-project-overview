# 风格 B：现代轨道交通工程汇报（rail-transit / V9，样式 v1.1.0）
 
用于真实卫星底图上的道路、管线、轨道、河道、分期实施范围 PPT 总图。源自用户确认的 V9：不重绘地理底图，只修改可编辑 SVG 的样式和标注。当前示例是匿名合成图，不含真实工程坐标或卫星影像。

## 先选风格，再执行
- 用户已点名风格时直接采用；未点名仍沿用原默认 A，不改变旧工程。
- 用户希望选择时展示 A [默认白卡](../../assets/example-overview.png) 与 B [轨道交通样张](../../assets/styles/rail-transit/example-preview.svg)。不因用户没有选择而卡住任务。
- 后续样式各自放在 assets/styles/<id> 与 references/styles/<id>.md，保持同一套真实坐标工作流。

## 固定工作流（弱模型照做）
1. 读取本项目 DXF/DWG 与原始影像，取真实 IMAGE 插入点、完整 U/V 轴、像素尺寸。递归展开 INSERT 块并应用变换；筛掉现状、参考和无关图层。明确分期、起终点、区域外轮廓、设计管线与道路红线，逐层列对象数。不得把未闭合线擅自当面或凭颜色猜管线。坐标变换按原技能 data-and-tools；统一左上原点，保持图幅与影像像素完全相同。任何缺失都如实报告。
2. 输出 geometry.svg（零原点 viewBox、固定画幅、单独 engineering-geometry 组），只包含真实路径/面及必要定义，不含旧标注。已有正确 SVG 时优先复用其几何；保留 d、points、transform 等几何属性，不做缩放平移或自动平滑。仅允许改变描边/填色属性。需要工程对象精确时不走默认概化流程。
3. 参照 style.json：道路红线红虚线+细白衬线；一期灰蓝、二期亮蓝+白衬线；河道青蓝半透明、轨道柔紫半透明。颜色参考 V9，宽度为视觉像素而非实际米制宽。原路径复制做衬线时各副本中心线一致。
4. 配置 scene.json：每个 label 的 anchor 是已确认的真实投影像素，不因排版而移动；box 为左上角 x,y,宽度，tip_base 为三角底边中心的 x。用四个主要标签时先同排，给左右留白；尽量使 anchor.x-tip_base 的符号相同、斜率相近。标签尺寸按文字收紧，边距至少 32/1600 画宽；避免覆盖铁路、水域和主管。若标签拥挤，先换 box 或 tip_base，再调整字号；不能移 anchor。脚本仅验证部分布局，不替代视觉审核。
5. 标签必须是一体封闭 path：圆角矩形底边两点→远端 anchor→返回底边。不是小三角加线；三角细长、尖端直接落在节点，重要节点大圆点（分界 > 起点 > 一般）。起点青绿、一期灰蓝、分界暖金、二期深蓝。每组内底框和文字、定位圆点分子组；AI 中移动框需用直接选择调整三角底边而保持尖端不动，禁止整体平移已固定的锚点。
6. 道路名称尽量落在各自红线内，主路找空白放横排；竖排汉字逐字正立，禁止旋转整串文字。河道可沿走势横斜标注或正立竖排。优先无框带深色衬字，减少标签数量。别用发光、复杂滤镜、浮夸立体按钮。
7. 分期示意尺与左下图例左边缘对齐，紧贴上方。两段独立半透明底色，分界 x 对齐真实分界锚点，起点 x 对齐真实起点；二期终点未知时只用方向箭头，不虚构桩号。该尺不是距离比例尺，必须标“分期示意”。仅适合横向从左到右的线路，其他方向需重新布局，不能强行套用。
8. 交付原生可编辑 SVG、同像素透明 PNG、真实影像合成预览；可提供关联版 SVG，影像相对路径固定并随素材包分发。不要把合成底色称为真实卫星图。底图缺失时仍可交付透明叠加层和明确标记的模拟底色预览。未经授权不将原图上传公开仓库。

## 运行命令
从技能目录运行 Node.js 18+（无 npm 依赖）：
```sh
node scripts/render_rail_transit.cjs assets/styles/rail-transit/example-geometry.svg assets/styles/rail-transit/example-scene.json out.svg
```
脚本只附加标注，不自动读取 DXF、不配准影像、不改变几何；原有 Python renderer 保持 A 风格。将项目 geometry.svg 与 scene.json 替换示例即可。脚本输出输入几何前缀的 SHA256，校验整段原始 SVG 字节保留。
用当前系统已安装的 Inkscape 或 CairoSVG 渲染 PNG；先确认字体可用，中文优先 Noto Sans CJK SC / Microsoft YaHei。不得附带字体文件。PNG 尺寸必须与 viewBox / 原图尺寸一致；如需插入 PPT 另存展示版，禁止拿展示裁切版作配准层。
 
## 验收（必做）
- 原始路径/变换、画布尺寸、每个工程锚点逐项比对；图像与 SVG 同尺寸、同原点。缺失真实底图，不宣称已配准。
- 每个标注独立命名 g；文字为 text，可编辑。节点圆心等于尖端坐标；路径封闭且没有额外独立引线。
- 检查标签框间距、越界、尖角互交、文字溢出、重要线面遮挡；确认正立竖排。脚本检查框越界、框互撞、部分宽度、尖角中心线交叉；其余人工看图。
- 分期尺起点、分界对齐；尺与图例不重叠，双色语义与标签一致，箭头不能冒充终点。
- 至少渲染一次完整预览、放大检查重要节点，再以 PPT 目标尺寸查看；发现问题改 scene.json 或样式，重复渲染。不得声称未经执行的测试通过。
- 公开样张只使用匿名合成几何，禁止复制真实工程文件。

### 重现与检查
运行本风格 Node.js CLI 后应产生与 example-overlay.svg 等价的 SVG；原始 geometry.svg 前缀必须保持原字节。geometry 样式由输入预先配置，脚本只增加注释；geometry 参数不是自动改线指令。对照已确认 example-preview.svg，检查所有标签明显倒圆角、白边足够粗、竖排正立、双色尺、起点和分界标识。预览版仅添加模拟底色与合成示意说明。不得以网页缩略图简化标签，也不得使用生成图重绘底图/线位。
