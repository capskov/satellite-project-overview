# 数据、坐标与底座经验

## 原图注册优先

原始影像像素、TFW像素中心、影像外边界、CAD插入原点及U/V轴不混为一谈。相差半像素时先解释约定，再决定是否调整；不能为了对齐新河道单独移动整个底图。旋转/斜切的影像按插入变换计算，不能只用轴对齐范围。

给出的PRJ和坐标先做一个已知位置检查。若直接转换落在明显不符的区域，不能继续把结果用于Google定位。用已有可靠GPX点位、桥涵、道路交叉和建筑形态交叉核对；记录不一致，保留原始资料，不擅自重配准。Google地图底图与影像日期可能不同，核对形态而不是宣称厘米级配准。

原底图与路由本已匹配时，图外排版应保持这一注册。河道描绘保留原始像素坐标或WCS坐标及变换，便于后续修改。

## CAD底座

按当前用户对CAD工具的要求选择底座和技能；出错时遵循当前用户要求。先读取实际版本、会话、工具schema和边界；正式图使用工作副本，保存、截图和磁盘读回的证据分别记录。

此前真实问题：

- Gateway进入时已调用一次tools/list；再次调用会被“only once”限制拒绝。应复用公开缓存/已获目录，或在首次返回时任务侧留存；不重写底座包、不绕过白名单。后续开发建议公开tool_catalog/get_tool_schema。
- 系统可用微软雅黑TTC不证明CAD原生text_style能创建。历史返回eFilerError，整批effects=none、事务回滚。原图字体可用时按授权沿用，独立插图文字可选系统字体；不为这件事默改全局FMP。
- 路径失效时，通过已支持的set_raster_path修复工作副本的原有影像引用，再检查注册和显示；找到了本地影像不等于坐标已配准。

这些是诊断线索，不是新环境必定发生的错误。不要复制旧句柄、固定MVID、原项目绝对路径或命令参数。未知写入只查询原请求；明确无效果回滚后才可修正方案，仍遵循本次用户要求。

## 语义与证据

专业代理保存图形能支持读到的图面几何，不自动包含全部原生设计属性。水源名称、交水关系、管径/长度来自当前资料或用户确认，不能仅从轨迹文件名称推断净水工艺或完整供水系统。

河道覆盖面分清“可见水面”“河槽/旱滩”“植被遮挡概化”。方案插图可统称河道范围示意，但不能拿来算水面面积或确定管理河界。面积和岸线测量转用相应工程/GIS资料。
